## Anti-Patterns Verdict

**AI slop? No.** Reads as a hand-built utility. OKLCH tokens disciplined, self-hosted Satoshi, no gradient text, no eyebrow scaffolding, no identical card grid, no ghost-card pattern (borders are single 1px lines, no paired wide box-shadow). Focus rings are best-in-class. The reticle/overlay scan UI is crafted, not generic.

**Deterministic scan (detect.mjs):** clean — `[]` findings on `apps/sweep/index.html`.

**One absolute-ban adjacency:** `.sr-header` uses `backdrop-filter: saturate(1.4)` with a semi-transparent `color-mix(... 88%, transparent)` background but NO `blur()`. This is not glassmorphism as decoration (it's an incomplete frosted header). Either add `blur(12px)` or drop the transparency. Not a ban violation, but a broken implementation.

## Overall Impression

A focused, fast utility that knows exactly what it is. The dark OKLCH theme is crisp, the reticle scanner UI is the highlight, and the new CSV/TXT/Copy export row reads as a clear group. The single biggest opportunity: the header is now floating (border removed per your request) but has no anchor — a functional `backdrop-filter: blur()` would give it weight without re-adding a line.

## What's Working

1. **Contrast is excellent.** `--ink` L=0.97 on `--bg` L=0.07 passes AAA. Accent-on-bg and accent-ink-on-accent both strong.
2. **Focus visibility.** `:focus-visible` 2px accent outline + offset, inherited radius. Inputs get the same. Rare and correct.
3. **Scanner craft.** Reticle with corner brackets, inset box-shadow mask, breathe + hit-flash. This is the personality of the app and it's well done.

## Priority Issues

### [P1] Mobile tap targets on results buttons are too small
- **What**: `.btn-sm` is `min-height: 32px; padding: 6px 12px`. CSV/TXT/Copy/Clear are visibly smaller than hero buttons on mobile.
- **Why it matters**: WCAG 2.5.5 recommends 44×44px. On a phone, these are the actions users tap most after scanning.
- **Fix**: At `@media (max-width: 640px)`, bump `.btn-sm` to `min-height: 40px; padding: 8px 14px` (or promote results actions to full `.btn` on mobile).
- **Suggested command**: `$impeccable adapt`

### [P1] Results table can overflow horizontally on mobile
- **What**: `.results-scroll` has `overflow-y: auto` but no `overflow-x` protection; no `table-layout: fixed`. A long URL in the Content column can force the table wider than the viewport.
- **Why it matters**: Page-level horizontal scroll on mobile is a jarring, broken-feeling interaction.
- **Fix**: Add `overflow-x: auto` to `.results-scroll`, `table-layout: fixed` to the table, and percentage column widths (e.g. Content 60%, Time `white-space: nowrap`).
- **Suggested command**: `$impeccable adapt`

### [P2] Header backdrop-filter is incomplete (no blur)
- **What**: `.sr-header` has `backdrop-filter: saturate(1.4)` + 88% transparent bg but no `blur()`.
- **Why it matters**: The intent is frosted glass; without blur it reads as slightly muddy semi-transparent background when content scrolls behind. Now that the border is gone, the header also floats unanchored.
- **Fix**: `backdrop-filter: blur(12px) saturate(1.4);` OR drop transparency and use solid `var(--bg)`.
- **Suggested command**: `$impeccable polish`

### [P2] HowTo JSON-LD has 5 steps but visible `<ol>` has 4
- **What**: JSON-LD `HowTo` splits "Open scanner" and "Scan codes" into two steps; the UI merges them into item 1.
- **Why it matters**: AEO inconsistency — the structured data describes a different process than what users see.
- **Fix**: Either split visible step 1 into two, or merge the JSON-LD steps to 4. Align both.
- **Suggested command**: `$impeccable clarify`

### [P3] Theme toggle tap target undersized on mobile
- **What**: Header theme button is `.btn-sm` (32px). Frequently tapped, sticky position.
- **Why it matters**: Lower-bound comfort on mobile; users tap this often.
- **Fix**: `min-height: 44px; min-width: 44px` for the theme toggle on mobile (invisible padding ok if visual size should stay small).
- **Suggested command**: `$impeccable adapt`

## Persona Red Flags

**Casey (Distracted Mobile User)**: The CSV/TXT/Copy/Clear buttons are 32px tall and clustered. One-handed thumb tapping will mis-hit adjacent buttons. The scanner viewport fits well and the hero reflows — but the results actions are the pain point. State is also not persisted across tab switches (scans lost if the user switches apps mid-session).

**Alex (Power User)**: No keyboard shortcuts. Start-camera, upload, base64, export — all mouse-only. No Esc-to-close on the base64 dialog (it's a `<dialog>` so native Esc should work — verify). No bulk select on results rows. For a "batch" scanner, power users will want to select-and-delete multiple rows.

**Sam (Accessibility)**: Focus rings are excellent. ARIA labels on theme toggle, camera preview, upload, textarea all present. `aria-live="polite"` on results count. The main gap: the reticle hit-flash is a visual-only success signal; screen readers get the status pill text, which is good. No major red flags — this is the strongest area.

## Minor Observations

- Light theme `--muted` (L=0.44) is AA but not AAA on white. Bump to L=0.38 for headroom.
- Base64 dialog at 375px: textarea ~295px wide. Usable, long strings wrap aggressively.
- Empty state "Nothing scanned yet." is appropriately quiet. Good.

## Questions to Consider

- Should scan results persist across sessions (localStorage)? A user who switches tabs loses everything.
- For a "batch" scanner, would multi-select + bulk delete beat per-row remove buttons?
- The 4 export buttons (CSV/TXT/Copy/Clear) — is Clear destructive enough to warrant a confirm, or is the flash-feedback enough?
